## Git 提交信息生成规范

### 1. 输出格式

仅单行输出，严格遵循 `<类型>: <描述>` 格式。无注释、无换行、无多余符号文字。

### 2. 合法类型

仅限：feat, fix, docs, style, refactor, test, chore, ci, build, revert

### 3. 字符限制

整行总字符数 ≤ 32，含类型、冒号、空格。

### 4. 排版规则

英文单词由两个及以上英文字母组成，前后若紧邻中文必须各保留一个半角空格。
数字连续串前后若紧邻中文必须各保留一个半角空格。
单个英文字母与中文连接构成的专有名词内部不加空格，整体视为中文词，前后与中文之间亦不加空格。

### 5. 描述内容规则

描述部分必须为纯名词短语，严禁包含任何动词或动作性词语。
彻底禁止以下词汇及其同义、近义表述，无论处于描述任何位置：
新增、添加、新建、修复、修改、更新、补充、完善、调整、优化、重构、回滚、移除、删除、升级、降级、合并、拆分、替换、集成、发布、启用、禁用。
描述直接陈述变更对象或范围，不加的等冗余助词，仅呈现主体名词。

### 6. 正确与错误对照

错误：chore: 新增 A 股简报规则及多份 A 股每日简报文件
正确：chore: A股简报规则及多份A股每日简报文件

错误：feat: 修复用户登录超时问题
正确：feat: 用户登录超时处理

错误：docs: 补充 API 接口文档
正确：docs: API 接口文档

错误：feat: 新增 3 月报告生成功能
正确：feat: 3 月报告

错误：refactor: 优化数据库查询性能
正确：refactor: 数据库查询

### 7. 语言要求

全程中文，类型关键词除外，禁止使用英文动词或混合描述。
